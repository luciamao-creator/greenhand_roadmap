## 1. 产品定义

面向**新手徒步爱好者**的 **C 端 AI 地图产品**。

核心机制：用 **RAG 预置经过检验的成熟线路**，把大模型输出约束在知识库内，**防止模型幻觉编造线路**误导用户。

## 2. 项目存在的目的（决定优先级排序）

本项目是**转型 AI 产品的求职作品集**，不是待市场化的商业产品。

| 展示目标 | 权重 | 含义 |
|---|---|---|
| RAG / embedding 等 AI 工程能力 | **主** | 检索链路、切片策略、防幻觉、可溯源、可观测 |
| 地图类 C 端产品的业务洞察 | 次 | 关键节点、跟随导航、离线路书、下撤判断等真实场景取舍 |

**推论（用于日常优先级裁决）**：能直接证明 AI 工程能力或产品判断的工作优先；后台精修、投稿审核等工作台功能**不产生展示价值，冻结投入**。

## 3. 必做（P0）

1. **RAG 知识库**：批量引入 **30–50 条全国成熟线路**，完成切片、embedding、检索
2. **C 端 chatbot**：回答「什么路线适合我」，返回知识库中的线路包，**每条推荐可点开溯源**
3. **地图能力**：关键节点渲染 + 跟随型导航
4. **离线路书**：自包含 PDF/HTML，无网可读
5. **出行准备**：按选定线路定制的 checklist、当日天气、下撤提醒
6. **轻度路线推荐**：基于用户使用情况
7. **可观测性**：生产管线每个环节的埋点与日志，供最终测试阶段归因

## 4. 明确不做（Non-Goals）

- 后台线路精修工具的持续投入
- 用户投稿流程、人工审核流、重型工作台
- turn-by-turn 语音导航
- 离线地图瓦片
- 线路生成精度的**中期**打磨（改为埋点归因，留到测试阶段集中处理）
- 百度地图（开放接口成本过高）→ 全部改用高德

> 注意：后台工作台**冻结而非删除**——它是产出 30–50 条线路的生产管线，删除即无语料来源。

## 5. 关键技术决策

| 项 | 结论 | 理由 | 状态 |
|---|---|---|---|
| 地图底座 | **高德** | 百度开放接口成本过高；现有地图代码仅后台一个预览组件，18 条线路清单无坐标数据，无 BD-09 存量，**迁移成本 ≈ 0** | `已确认` |
| 导航 | **跟随型**：定位 + 轨迹叠加 + 点到线偏航判定 + 关键节点/岔路接近提醒 + 下撤点提醒；**不做 turn-by-turn** | 用户确认 | `已确认` |
| 离线路书 | **自包含 PDF/HTML**（路线概要 + 节点经纬度 + 海拔剖面 + checklist + 下撤点 + 紧急联系），**不含地图瓦片** | 高德/百度 Web SDK 均不支持离线瓦片，真离线地图是另一量级工程 | `已确认` |
| Embedding | **阿里百炼 `text-embedding-v3`**（DashScope，1024 维） | 复用已有 `AGENT_PREFILL_PROVIDER=qwen` / 百炼通道，不引入新供应商 | `已确认` |
| 向量存储 | **暂不引入 pgvector**；线路语料文件化 + 内存余弦检索，检索层抽象为 `Retriever` 接口，保留 `PgVectorRetriever` 实现位 | 已验证：本机无 Postgres / 无 brew / 无 docker；Cloud Studio 沙箱同样无 Postgres 且无预置环境变量。50 条线路约数百 chunk，内存检索 < 1ms，引入 pgvector 属过度工程。**切换阈值**：chunk 数 > 5000 或需要在线增量写入时切换 | `暂定假设` |
| 端形态 | **移动端优先 H5**（Next.js + 高德 JS API，App 观感），同一套代码在浏览器与微信内置浏览器中运行；**不做小程序** | 见 §6 | `已确认` |
| 部署目标 | **腾讯云 CloudBase**（Node 云托管），公网可访问；先用 CloudBase 默认二级域名，不自购域名、不做 ICP 备案 | 兼顾国内访问速度与 Next.js Node 运行时 | `已确认` |
| 微信入口 | 通过微信内置浏览器打开 H5 链接即可转发分享，不额外开发小程序；中期若确需小程序用 `web-view` 内嵌现有 H5 | 见 §6 | `已确认` |

### 5.1 已实测验证的结果（2026-09-15）

| 项 | 实测结果 |
|---|---|
| 百炼 LLM `qwen-plus` | ✅ HTTP 200，可用（13 tokens 冒烟） |
| 百炼 Embedding `text-embedding-v3` | ✅ HTTP 200，可用，**实测返回 1024 维** —— pgvector 后续必须按 `vector(1024)` 建表，此数字不可凭记忆填写 |
| 高德 `NEXT_PUBLIC_AMAP_JS_KEY` | ✅ SDK 入口返回 HTTP 200 / 946KB，无任何一个 Key 无效错误码 |
| 高德 `NEXT_PUBLIC_AMAP_SECURITY_CODE` | ⏳ 待阶段 4 验证（Web端 Key 的有效性最终只能在浏览器 `new AMap.Map()` 时确认，服务端 curl 测不出来） |
| `AMAP_WEB_SERVICE_KEY` | ⬜ 未填写，阶段 6 天气/地理编码功能需要时补 |

> **注**：高德 Web端 Key 的"有效性"无法通过服务端请求判定——`webapi.amap.com/maps` 无论 Key 是否有效都返回 SDK 脚本，校验发生在浏览器实例化地图时。因此上表第三行的 ✅ 仅代表**通过下载阶段校验**，不代表已确认可用。

## 6. 端形态与部署（已定）

**结论：移动端优先 H5 + 腾讯云 CloudBase，不做小程序。**

### 6.1 决策理由

1. H5 在**浏览器与微信内置浏览器中是同一套代码**，零额外客户端成本，且能在微信里转发分享——这正是"体验好"的部分，不需要小程序也能拿到
2. **保住高德**：微信小程序只能使用原生 `<map>` 组件（底层腾讯地图），高德无小程序地图渲染方案，走原生小程序等于推翻 §5 的地图选型
3. 免去小程序账号、**ICP 备案**、类目审核的数周周期
4. 服务端能力层（线路数据、RAG/embedding/检索、chatbot、checklist、天气）**与端形态 100% 无关**，任何端形态均可复用；仅「地图渲染 + 定位 + 导航交互」因端而异，约占客户端 20%

### 6.2 域名

使用 **CloudBase 提供的默认二级域名**，不购买域名、不做 ICP 备案。域名确定后须回填至高德控制台的 Key 白名单。

> `暂定假设`（需实测确认）：未备案域名在微信内置浏览器中偶有拦截。上线后第一时间用微信打开实测，若被拦截再启用备用域名方案。

### 6.3 云端部署约束

- **HTTPS 是硬要求**：浏览器仅在 secure context 下允许 `navigator.geolocation`，**无 HTTPS 则跟随导航的定位直接失效**
- **Node 运行时**：应用含 API routes，需 Node 云托管，不可使用纯静态 CDN
- **成本护栏必须内置**（见 §10 注）：公网开放后每个访问者都在消耗百灵 Key，embedding + LLM 按 token 计费
- **部署卫生**：部署产物只含必要文件，不得包含 `docs/`、`demo/`、`SOUL.md`、`.deploy/` 自身
- **高德 Key 护栏**（两种 Key 策略相反，勿混）：
  - `Web端(JS API)` Key 随前端 bundle 明文下发，任何人可获取 → **上线前必须在控制台配置域名白名单**，本地 `localhost` 开发阶段不填
  - `Web服务` Key 仅服务端使用、不外泄 → **IP 白名单留空**（云托管出口 IP 可能变动，填写容易导致线上失效）
  - 安全密钥：MVP 阶段使用官方允许但不推荐的**明文方式**；公网开放前改为 `serviceHost` **代理转发**（Next.js API route 转发 `restapi.amap.com`），此为官方标注「强烈建议使用」的方式
  - 控制台设置每日配额上限与告警
  - **几何回填（2026-09-15 已执行）**：`scripts/sync-geometry.py` 用高德 Web服务 v3 地理编码 + POI 搜索为 40 条线路回填起终点真实坐标。落地前强制三级核验，宁可留空也不写未核实坐标：
    1. 省/市一致
    2. 区/县一致：不匹配则降级标记 `ok_cross_district`（仍写入，交人工抽查，如东湖磨山横跨洪山/武昌）；区县缺失直接拒绝
    3. 精度白名单：只接受 `兴趣点/门牌号/道路/交叉口/村庄/景点/风景名胜`，**拒绝市/区县级行政中心**（实测踩雷：大连「唐王殿遗址」的地理编码返回 `level=市`、区县为空，会把大连市中心 25km 外当终点写进去）
    - 名称匹配用**专名**而非全名（剥掉「游客中心/观景台」等通用后缀），否则「龙脊天路游客中心」会命中任何「游客中心」
    - **25km 距离护栏**：一条步道两端不可能相距 25km 以上，超限且为跨区降级匹配的点清空为 `far_review` 交人工
    - 结果：40 条全部写入真实坐标（33 条已核验 `ok` + 3 条新补 `ok` + 4 条 `ok_cross_district`）；原 3 条打飞的线路（龙脊天路、歌乐山、帽峰山）已直接从 `first-launch-30-route-candidate-pool-v1` 的候补线中替换为 3 条可干净解析的新手友好线路：**厦门曾山步道、福州福道（象山段）、江门圭峰山休闲徒步线**。报告见 `logs/geometry-sync-*.json`
    - 配额提示：高德 Web服务地理编码免费额度 3000 次/日，重跑需分批

### 6.4 中期选项

若确需小程序 **原生**体验再做极大投入，采用 `web-view` 内嵌现有 H5，客户端代码零改动，仅增加一层薄壳。

## 9. 埋点要求

生产管线每个环节输出一条 trace（建议 JSONL），至少覆盖：

```
清单导入 → 地图补参 → agent prefill → 入库 → 切片 → embedding → 检索 → 回答生成
```

每条 trace 记录：`trace_id`、`route_id`、`环节`、`输入摘要`、`输出摘要`、`耗时`、`token 消耗`、`成功/失败`、`失败原因`。
目的：最终测试阶段对"线路生成不准确"做归因，同时作为 AI 工程可观测性的展示材料。
