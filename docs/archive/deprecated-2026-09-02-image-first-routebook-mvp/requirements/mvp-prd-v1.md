## 2. 产品概述

### 2.1 产品一句话

- 面向徒步新手小白的离线路书工具，帮助用户从“不知道去哪”到“敢去、会去、能安全回来”。

### 2.2 产品定位

- 本产品不是面向发烧友的专业轨迹工具。

- 本产品不是通用地图导航平台。

- 本产品是面向新手的 `内容驱动 + 安全感驱动` 路书工具。

### 2.3 核心价值

- `选择更简单`：帮助用户快速找到真小白可走、审美友好的成熟路线。

- `在途更安心`：通过关键参照物、禁区提示、下撤提醒、天气预警降低恐慌感。

- `准备更完整`：通过强制 checklist、应急信息和离线路书包降低准备不足风险。

## 3. 用户定义

### 3.1 核心用户

- 徒步经验 `0-5 次` 的城市休闲型新手。

- 主要动机是健康、风景、周末放松、轻成就感，而不是身体极限或专业挑战。

- 对岔路、天气、信号、装备准备更敏感。

### 3.2 非目标用户

- 野线爱好者；

- 极限长线用户；

- 专业轨迹记录和数据分析重度用户；

- 以社交组队为核心诉求的用户。

## 4. 用户痛点与对应方案

| 痛点        | 说明                | MVP 对应方案              |
| --------- | ----------------- | --------------------- |
| 不知道去哪里    | 不会判断难度，也不知道什么适合自己 | 地图点位浏览 + 精选线路库 + 体验标签 |
| 岔路恐慌      | 看到分叉时不知道该怎么判断     | 关键岔路重点图 + 参照物卡片       |
| 离线与信号焦虑   | 担心山区无信号、地图打不开     | 离线路书包 + 本地图像优先        |
| 天气突变      | 不知道是否有预警或突发变化     | 常驻天气 banner + 官方预警入口  |
| 误入禁区或离开步道 | 容易跟错、抄近路、误入野线     | 禁区重点图 + 高风险文案提示       |
| 时间规划失败    | 不清楚何时需要下撤         | “距离建议下撤还有 X 小时” 常驻提醒  |
| 物资准备不足    | 不知道带什么、不知道是否漏项    | 进入路书前强制 checklist     |

## 5. 产品目标

### 5.1 MVP 目标

- 用最小可行范围验证：新手用户是否愿意使用 `离线路书包` 完成一次安心徒步出行。

### 5.2 非目标

- 不验证复杂社交关系；

- 不验证用户上传路线；

- 不验证完整导航替代；

- 不验证完整商业化体系。

## 6. MVP 范围

### 6.1 功能范围

#### A. 线路发现

- 中国地图上展示首期线路点位；

- 支持按省份查看：四川、浙江、广东、福建；

- 支持按体验标签快速筛选；

- 线路卡片展示基础信息：

  - 线路名；

  - 所在城市/区域；

  - 预计时长；

  - 难度等级；

  - 1-3 个主标签。

#### B. 线路详情页

- 展示适合新手的理由；

- 展示路线核心参数：距离、时长、爬升、最佳季节；

- 展示地貌与景观表达；

- 展示新手重点风险；

- 提供离线路书包下载入口；

- 展示应急联系和天气入口。

#### C. 离线路书包

- 用户可下载某条线路的离线路书包；

- 路书包至少包含：

  - 路线总览图；

  - 分段图；

  - 岔路重点图；

  - 关键参照物卡片；

  - 禁区重点图；

  - 基础路线数据；

  - 下撤点；

  - 应急联系信息；

  - checklist 模板。

- 弱网或无网时优先使用本地资源展示。

#### D. 在途路书页

- 展示当前路线阶段；

- 展示关键参照物；

- 展示重要岔路提醒；

- 展示禁区与不要进入的区域；

- 展示“距离建议下撤还有 X 小时”；

- 展示天气 banner。

#### E. 天气与预警

- 接入天气 API；

- 路书页展示常驻天气提示；

- 支持点击进入官方预警信息。

#### F. 出发前 checklist

- 用户进入离线路书前强制弹出；

- 支持逐项勾选；

- 支持保存本地；

- 支持天气加严项。

### 6.2 明确不做

- 登录注册；

- 社区和评论；

- 用户上传路线；

- 复杂消息通知体系；

- 专业导航指令；

- 完整离线地图瓦片系统；

- 发烧友数据分析面板。

## 7. 信息架构

- 首页

- 地图发现页

- 路线详情页

- 离线路书包页

- 在途路书页

- checklist 弹层/页面

- 天气预警详情页

- 安全说明页

## 8. 关键体验要求

### 8.1 体验原则

- 所有表达优先服务于新手理解，不服务于专业感堆砌；

- 在途页优先回答“我是不是走对了”，而不是优先展示专业参数；

- 视觉需要体现地形地貌特征和自然审美，不做冷冰冰地图壳。

### 8.2 审美表达要求

- 每条路线应具备地貌关键词；

- 地图图像需体现编辑加工痕迹，而不是仅展示原始底图；

- 重要节点应具有人类可识别的参照物图像或图示；

- 标签表达需兼顾用户决策效率与气质表达。

### 8.3 标签体系原则

- 主标签框架固定为：

  - 景观审美；

  - 安全感；

  - 轻松成就。

- 允许在框架下扩展表达，例如：

  - 景观审美：`溪谷感`、`林荫感`、`山脊视野好`、`适合拍照`

  - 安全感：`成熟步道`、`路标清楚`、`下撤明确`

  - 轻松成就：`周末可完成`、`上手友好`、`首次徒步可尝试`

## 9. 内容范围

### 9.1 首期省份

- 四川

- 浙江

- 广东

- 福建

### 9.2 首期内容规模建议

- 每省 5-10 条；

- 首期总量 20-30 条；

- 优先成熟公开线路；

- 优先城市周边或交通可达线路。

## 10. 业务规则

- 未下载离线路书包时，不应鼓励用户直接进入在途使用；

- 高风险天气或明显风险提示需要醒目展示；

- 产品文案不得鼓励冒险、野线或离开成熟步道；

- 禁区表达必须清晰，不允许弱化。

## 11. 数据与埋点建议

- 线路列表曝光；

- 线路详情点击；

- 路书包下载；

- checklist 完成；

- 天气预警点击；

- 在途页打开；

- 应急联系方式点击；

- 用户主观安心评分。

## 12. 成功标准

- 用户能在 3 分钟内选到一条适合自己的线路；

- 路书详情页能清楚解释“为什么适合新手”；

- 路书包下载和 checklist 构成使用前关键闭环；

- 在途页能明确提供参照物、岔路和禁区判断信息；

- 产品整体体验体现“安全感 + 审美 + 可执行性”。

## 13. 风险与依赖

- 路线内容质量是核心风险，低质量内容会直接伤害用户安全感；

- 天气与预警数据依赖外部接口稳定性；

- 小程序阶段的离线能力需严格控制承诺边界；

- 处理过的地图图像生产成本较高，需要内容生产流程支撑。

## 14. 长期版本方向

- 用户登录；

- 收藏、走过、成就体系；

- 更丰富线路库；

- 更强通知能力；

- 更强离线与连续在途安全能力；

- 可能扩展至 APP。
