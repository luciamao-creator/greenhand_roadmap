# MVP 产品关键决策归档

## 文档状态

- 状态：已确认

- 日期：2026-09-02

- 适用阶段：MVP 方案设计、研发准备、内容生产准备

- 上位约束：`SOUL.md`

## 背景

- 项目目标是面向徒步新手小白，提供区别于发烧友产品的路书体验。

- 产品核心不是通用地图导航，而是帮助新手完成“选线 - 准备 - 在途判断 - 安全下撤”的闭环。

## 已确认决策

### 1. MVP 载体

- MVP 采用 `微信小程序`。

- 原因：冷启动门槛更低，便于快速验证新手用户是否愿意使用路书完成一次安心出行。

### 2. 核心产品对象

- MVP 的核心产品对象是 `离线路书包`。

- 若没有离线路书包，本产品对用户的价值会明显不足。

### 3. 离线能力边界

- MVP 不承诺“完整离线地图导航”。

- MVP 的离线能力定义为：`结构化路线数据 + 处理过的地图图像 + 关键节点卡片 + 风险提醒 + checklist`。

- 产品对外表达应聚焦“新手友好的离线路书与安全辅助”，避免暗示“跟着产品走即可安全完成路线”。

### 4. 地图表达策略

- `本地图像优先，在线地图辅助`。

- “处理过的地图图像”是 MVP 的核心表达方式，不可降级为纯抽象折线。

- 路书包内至少应包含：

  - 总览图；

  - 分段图；

  - 岔路重点图；

  - 禁区重点图；

  - 关键参照物卡片。

### 5. 安全边界

- 不引导用户进行野线、抄近路或未开发路径探索。

- 只收录 `成熟、公开、适合新手` 的线路。

- `sources/` 为只读参考资料，不得修改。

### 6. 首期省份范围

- 首期省份确定为：`四川、浙江、广东、福建`。

### 7. 标签框架

- 首期主标签框架固定为：

  - `景观审美`

  - `安全感`

  - `轻松成就`

- 具体标签表达允许在该框架下扩展，但不得偏离新手视角。

### 8. 内容准备方式

- 采用 `按标准反推素材需求` 的方式推进。

- 先建立统一线路内容标准，再由业务侧按标准准备线路素材。

### 9. 实施节奏

- 第一阶段：输出 `可评审 PRD + 技术方案 + 信息架构 + 素材标准`。

- 第二阶段：做 `3-5 条样例线路` 的完整 MVP 闭环演示。

- 第三阶段：扩展至首批精品线路库，并进行真机/试走验证。

## 影响范围

- 产品范围：MVP 只做新手安全感路书，不做通用地图平台。

- 技术范围：优先设计离线路书包和内容生产体系，而不是优先设计复杂导航引擎。

- 内容范围：首批线路需按统一标准人工编辑，不依赖纯自动抓取生成。
