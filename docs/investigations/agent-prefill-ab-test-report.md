# 大模型预填能力 A/B 评测报告 (DeepSeek vs Qwen)

## 1. 评测背景
本项目核心的后台自动预填链路 (`agent-prefill`) 依赖大模型的结构化输出能力，以减少运营手动录入路线信息的成本。为了决定 MVP 阶段的默认大模型提供商，我们在本地开发环境对同一条测试路线（“雁荡山灵峰环线”）进行了 A/B 对比测试。

测试对象：
*   **DeepSeek (V3)**: `deepseek-chat`
*   **阿里百炼 (Qwen)**: `qwen-plus`

## 2. 评测维度与真实落库结果对比

### 2.1 短摘要 (`summary_short`)
*   **DeepSeek**: “雁荡山灵峰环线，短而平缓，适合初次体验山野徒步的游客。”
*   **Qwen**: “雁荡山灵峰景区内环形徒步线，全程约 2.8 公里，海拔爬升不足 120 米，石板路与缓坡步道为主，串联观音洞、北斗洞、合掌峰等核心观景点，适合首次接触山野徒步的新手。”
*   **评价**: Qwen 展现出了极强的内容密度和先验世界知识，直接输出了具体的距离、爬升和核心景点名称，更像一篇成熟的户外攻略。DeepSeek 比较干瘪。

### 2.2 新手适配理由 (`beginner_fit_reason`)
*   **DeepSeek**: “路线短、爬升少、指示清晰，且紧邻景区步道，补给和撤退方便，适合体能一般的初学者。”
*   **Qwen**: “路线封闭于成熟景区内，标识清晰、无岔路迷途风险；全程有休息亭、卫生间及补给点（灵峰入口/出口处）；平均坡度＜8%，无悬空栈道或暴露岩壁段。”
*   **评价**: Qwen 在安全性和专业维度上表现更好，使用了“无暴露岩壁”、“平均坡度”等徒步专业词汇，直击小白痛点。

### 2.3 标签 (`route_tags`)
*   **DeepSeek**: 偏向原子化标签（`轻松`, `环线`, `新手`, `奇峰怪石`, `洞穴寺庙`）。
*   **Qwen**: 偏向复合型、场景化标签（`轻松环线`, `全程标识完备`, `无暴露路段`, `经典景区内线`）。
*   **评价**: Qwen 的标签更符合我们“新手避坑路书”的产品定位，能提供直接的情绪价值和安全感。

### 2.4 常见问题 (`route_faqs`)
*   **DeepSeek**: 泛泛而谈，例如“一般 2-3 小时可完成”、“景区入口有小卖部”。
*   **Qwen**: 信息极度具体，甚至包含了票价（“需购买雁荡山景区通票...成人 120 元”）、具体补给点位置（“观音洞前、北斗洞旁”）、以及雷暴天气下的具体避险动作（“就近进入观音洞室内区域暂避”）。
*   **评价**: Qwen 在不依赖外部 RAG 的情况下，单靠预训练权重就给出了极具操作性的回答。

### 2.5 JSON 结构化输出稳定性
*   **DeepSeek**: 一次通过，严格遵守 JSON Schema 且所有字段类型（字符串、整数等）完全正确。
*   **Qwen**: 在置信度分数（`credibility_score`）等要求为整数的字段上，出现过返回小数（如 `0.95`）导致入库报错的情况。
*   **评价**: DeepSeek 的指令遵循和代码级输出稳定性更强。但我们在接入层（`agent-prefill-client.ts`）补齐了针对 Qwen 的类型防抖与归一化逻辑后，该问题已被妥善解决。

## 3. 结论与决策

1.  **产品表现层面，Qwen (qwen-plus) 完胜。** 在尚未接入复杂外网 RAG 检索的 MVP 阶段，Qwen 凭借更丰富的中文旅游/户外语料，能直接产出可用度极高的路书草稿，大幅降低运营初期的冷启动门槛。
2.  **工程实现层面，已解决 Qwen 的类型不稳定问题。**
3.  **最终决策**：**将阿里百炼 (Qwen) 设为后台流水线的默认大模型 Provider。**

## 4. 后续配置指引
当前 `.env.example` 和 `README.md` 已将默认环境配置更新为：
```bash
AGENT_PREFILL_PROVIDER=qwen
AGENT_PREFILL_API_URL=https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions
AGENT_PREFILL_MODEL=qwen-plus
```
DeepSeek 保留为备用降级方案，仅在配置调整时启用。
