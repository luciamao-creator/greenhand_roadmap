## 2. 目标

- 将当前 `精选路线库 + 路线跟随型导航` 的 MVP 定义落成页面层结构；

- 明确哪些页面是 `必做`、哪些是 `增强项`；

- 明确每个页面的产品职责，避免出现“技术上能做但页面上不该出现”的功能堆叠；

- 统一整体交互风格，保持 `OTA App + 地图 App` 的简约清爽体验。

## 3. 架构原则

### 3.1 一级结构原则

- 全局只围绕三条主链路组织：

  - `选线`

  - `准备`

  - `在途`

- 不以“功能分类”作为主导航逻辑；

- 不把用户暴露在复杂地图工具和过多入口前。

### 3.2 信息优先级原则

- 一级信息：

  - 适不适合我；

  - 现在能不能去；

  - 去了之后怎么不慌。

- 二级信息：

  - 时长、距离、爬升；

  - 标签；

  - checklist；

  - FAQ。

- 三级信息：

  - 证据来源；

  - 规则解释；

  - 详细提示文本。

### 3.3 交互原则

- 地图页优先全屏，详情页优先卡片化；

- 详情信息尽量放在底部抽屉、卡片列表、分组模块中；

- 少做分散入口，多做顺序式决策；

- 关键 CTA 统一，避免同屏出现多个主按钮竞争。

## 4. 全局信息架构

### 4.1 主导航结构

- `发现`

  - 首页

  - 路线发现

  - 标签筛选

- `路线`

  - 路线详情

  - FAQ/解释

  - 风险说明

- `准备`

  - 出发前准备

  - checklist

  - 天气预警

- `在途`

  - 导航页

  - 偏航提醒

  - 下撤提示

### 4.2 页面流转主路径

```text
首页
  -> 路线发现页
  -> 路线详情页
  -> 出发前准备页
  -> checklist
  -> 在途导航页
  -> 天气/风险/下撤辅助页
```

### 4.3 MVP 不进入主结构的内容

- 社区；

- 发帖；

- 用户上传路线；

- 成就体系；

- 登录中心；

- 重型设置中心；

- 复杂个人主页。

## 6. 页面定义

### P01 首页

#### 页面目标

- 快速建立产品定位；

- 用最少信息帮新手开始选线；

- 提供低门槛入口，不制造复杂感。

#### 核心模块

- 顶部城市/省份入口；

- 首页主标题区；

- 今日/本周推荐路线区；

- 三个快捷筛选入口：

  - `更轻松`

  - `风景更好`

  - `更安心`

- 首批省份入口；

- 安全说明轻入口。

#### 交互要求

- 首页不直接塞大地图；

- 首屏优先用卡片和主题入口，让用户先做“方向决策”；

- 若有地图预览，只作为辅助模块，不是主界面中心。

#### 审美要求

- 接近 OTA 首页的“目的地灵感 + 快速筛选”逻辑；

- 采用大图卡片、小标签、轻阴影和大留白。

### P02 路线发现页

#### 页面目标

- 将路线库收敛成可筛选、可比较、可快速决策的列表；

- 用标签替代复杂专业术语。

#### 核心模块

- 顶部筛选栏：

  - 省份；

  - 城市；

  - 标签；

  - 时长；

  - 强度。

- 列表视图；

- 可切换的小地图预览；

- 推荐排序；

- 空状态与无结果提示。

#### 路线卡字段

- 路线名称；

- 区域；

- 时长；

- 距离；

- 累计爬升；

- 1-3 个标签；

- 一句新手理由；

- 当前天气友好度或时间友好度提示。

#### 交互要求

- 默认列表优先，地图为辅助；

- 地图切换不是独立页面，而是列表页内的一种视图；

- 避免做专业 GIS 风格的图层切换。

### P03 路线详情页

#### 页面目标

- 回答“这条线适不适合我”；

- 回答“如果去，我最需要知道什么”；

- 为出发前准备和开始导航提供可信入口。

#### 页面结构

- 顶部路线封面区；

- 路线摘要区；

- 新手适配说明区；

- 关键参数区；

- 风险与不适合条件区；

- 天气摘要区；

- FAQ/解释区；

- checklist 入口；

- 开始导航 CTA。

#### 核心字段

- 路线名；

- 省份/城市；

- 路线类型；

- 时长、距离、爬升；

- 标签；

- 适合新手理由；

- 不建议出发条件；

- 下撤逻辑摘要。

#### 交互要求

- 首屏不堆参数；

- 参数区要比 OTA 酒店详情更轻，而比地图 App POI 更完整；

- FAQ 默认折叠，避免页面过长。

### P04 出发前准备页

#### 页面目标

- 把“知道去哪”转成“准备好再去”；

- 在出发前最后一次做保守提醒。

#### 核心模块

- 出发前状态判断：

  - 天气是否合适；

  - 当前时间是否合适；

  - 是否满足基础准备；

- checklist 总览；

- 重点加严项提醒；

- 风险二次确认；

- 继续开始导航 CTA。

#### 交互要求

- 这是一个“确认页”，不是资讯页；

- 重点文案应保守而明确；

- 不允许通过复杂说明稀释风险提示。

### P05 checklist 页面/弹层

#### 页面目标

- 用最低认知成本让用户确认必要物资。

#### 模块结构

- 基础必带；

- 天气加严项；

- 风险加严项；

- 选带项；

- 完成确认按钮。

#### 交互要求

- 默认按优先级排序；

- 必带项固定在最上；

- 可显示“为什么推荐”说明；

- 不展示生成式长文本，优先展示结构化清单。

### P06 在途导航页

#### 页面目标

- 在用户已经出发后，优先降低慌张感；

- 回答“我是不是还走对了”。

#### 页面结构

- 全屏地图区；

- 底部导航抽屉；

- 顶部简洁状态栏；

- 浮动主操作按钮。

#### 地图层信息

- 当前定位点；

- 推荐路线；

- 当前阶段；

- 关键节点；

- 岔路点；

- 下撤点；

- 风险点。

#### 抽屉区内容

- 当前状态摘要；

- 距离下一关键点；

- 是否偏航；

- 距离建议下撤节点或建议时间；

- 当前天气风险。

#### 交互要求

- 地图为绝对主角；

- 抽屉默认半展开；

- 不在导航页堆 FAQ 和长段说明；

- 风险提醒采用顶部 banner 或底部卡片，不弹过多模态框。

#### 审美要求

- 参考地图 App 的“地图主界面 + 轻面板”结构；

- 颜色克制，路线线条清晰但不过度鲜艳。

### P07 天气预警详情页

#### 页面目标

- 把天气从“背景信息”升级为“行动建议”。

#### 核心模块

- 当前天气概览；

- 当天风险提示；

- 官方预警状态；

- 行动建议：

  - 继续；

  - 提前；

  - 暂缓；

  - 取消。

#### 交互要求

- 语言必须面向新手；

- 不只展示气象参数，还要给出产品内的保守解释。

### P08 安全说明页

#### 页面目标

- 统一解释产品的安全边界和路线库边界；

- 避免用户误解产品承诺。

#### 核心模块

- 产品不推荐什么；

- 为什么只收录成熟公开路线；

- 为什么导航是辅助，不是保证；

- 什么情况下应该放弃出发或中途回撤。

#### 交互要求

- 入口常驻但不强打扰；

- 页面语言简洁直接，不写官样长篇免责声明。

## 7. P1 页面定义

### P09 FAQ 全量页

- 承接详情页中折叠 FAQ 的完整展开；

- 用于重度用户进一步理解路线，不作为首屏强曝光。

### P10 推荐解释页

- 承接“为什么推荐这条给你”的完整解释；

- 可作为 AI 价值展示页，但必须基于结构化事实。

### P11 路线状态异常页

- 当路线暂停推荐、临时关闭、天气高风险时展示；

- 以保守提示替代继续引导。

### P12 下撤说明页

- 承接在途页中“此处可收手”的详细解释；

- 只在必要时进入，不常驻主流程。

## 10. 关键交互路径

### 10.1 标准路径

```text
首页
-> 路线发现页
-> 路线详情页
-> 出发前准备页
-> checklist
-> 在途导航页
```

### 10.2 风险中断路径

```text
路线详情页
-> 天气预警详情页
-> 返回详情页
-> 暂缓出发 / 继续准备
```

### 10.3 在途收手路径

```text
在途导航页
-> 下撤提示
-> 下撤说明页
-> 返回导航页或结束本次路线
```

## 11. 审美落地要求

- 首页参考 OTA 的目的地浏览感，但必须更克制；

- 发现页优先列表卡片，不做一上来就强地图压迫；

- 详情页卡片层级清晰，重点信息靠前；

- 导航页尽量接近地图 App 的沉浸式体验；

- 色彩使用白、浅灰、低饱和绿色/蓝色为主，风险色只在关键时刻出现；

- 文案风格克制、可靠、不过度热血，不制造“征服山野”的情绪。
