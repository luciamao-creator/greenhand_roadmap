## 2. 文档目标

- 给出首发阶段优先考虑的 `30 条路线候选池`；

- 保证候选池符合当前产品边界：成熟公开、可查可证、适合新手；

- 让后续 `后台录入与审核页面设计 V1` 能围绕真实候选对象展开，而不是抽象设计；

- 为后续录入、补证据、首发排期提供单一事实来源。

## 3. 使用说明

- 本文档是 `候选池`，不是最终已批准入库清单；

- 候选池中的每条线路仍需经过：

  - 证据补齐；

  - 新手友好度复核；

  - 一票否决项检查；

  - A/B/C 可信度评级；

- 本文档优先解决的是：`先选哪一批路线最值得投入制作成本`。

## 4. 首发筛选原则

### 4.1 当前采用的首发偏向

- 优先 `城市周边 1 日内可往返`；

- 优先 `景区步道 / 森林步道 / 古道 / 郊野公园`；

- 优先 `路线逻辑清楚、入口明确、退出成本低`；

- 优先 `有公共化迹象`：

  - 游客中心；

  - 停车场；

  - 公交接驳；

  - 景区导览；

  - 茶馆 / 小卖部 / 古镇 / 补给点；

- 优先 `能让新手获得风景与成就感，但不鼓励冒险`。

### 4.2 当前刻意回避的路线类型

- 高海拔和高反变量明显的景区线；

- 核心体验依赖野路、手脚并用、绳索攀爬的线路；

- 大段无遮挡暴晒、涉水、礁石海岸风险高的线路；

- 资料虽火，但难以给新手形成稳定预期的线路。

### 5.1 层级定义

- `A1`

  - 建议优先进入后台录入与审核流；

  - 预计更容易达到 A 级可入库标准。

- `A2`

  - 保留在首发候选池内；

  - 但需要补更多证据，或存在一定强度/季节/人流变量；

  - 适合作为二线备选。

## 8. 当前明确不建议放进首发 30 条的典型线路

以下类型即使知名，也不建议进入当前首发候选池：

- 四川高海拔雪山景区长线

  - 原因：高反、天气波动、强度和新手稳定预期不匹配。

- 深圳东西涌 / 典型海岸穿越线

  - 原因：虽成熟且知名，但海岸暴晒、礁石与边坡环境对纯新手解释成本高。

- 厦门岛外高海拔与强爬升线路

  - 原因：首批更应优先城市山海步道与成熟景区短线。

- 泉州 / 浙江若干需要长距离或高台阶密集爬升的古道深度线

  - 原因：适合作为后续“新手进阶”产品层，而不是首发主盘。

## 9. 对后台设计的直接启发

这份候选池会直接影响后续 `后台录入与审核页面设计 V1`：

- 后台必须支持 `城市步道 / 景区步道 / 古道 / 森林步道` 四种主要路线类型；

- 后台必须支持 `短线版本` 与 `精华分段` 的录入，而不是默认所有路线都按整条长线处理；

- 后台审核页必须单独检查：

  - 入口是否明确；

  - 公共化迹象是否成立；

  - 节假日拥挤与天气风险是否可表达；

  - 是否存在更保守的推荐走法；

- 后台发布页应支持 `首发优先 / 候补补证据 / 淘汰` 三类建议状态。
