## 2. 文档目标

- 把后台页面设计与字段清单落成可画线框图的页面骨架；

- 明确每页的低保真布局、主交互、关键状态和页面跳转；

- 让后续后台原型实现不再从空白页面开始猜结构；

- 保证后台原型优先服务 `候选 -> 录入 -> 审核 -> 发布` 的主生产链。

## 3. 原型原则

### 3.1 先效率，后装饰

- 低保真阶段只验证信息层级、布局关系和操作顺序；

- 不在本阶段讨论视觉皮肤、品牌细节和动效润色；

- 所有页面优先保证长表单、表格、侧栏、抽屉的组合效率。

### 3.2 工作台优先

- 后台不是 CMS 首页，而是单条路线生产流水线；

- 内容录入员默认围绕 `候选池 -> 工作台 -> 分页录入 -> 提交审核` 工作；

- 审核员和发布员只看到与自己决策相关的摘要，不回灌过多编辑入口。

### 3.3 最小录入优先

- 新增路线默认先录入最小事实，而不是展开完整大表单；

- 基础参数、标签候选、来源摘要默认先由 Agent 补全；

- 地图空间真相优先来自地图 API，同步失败时保持缺失，不允许凭感觉补地图真相；

- 用户上报的节点、下撤点、风险点必须进入待审核状态，不直接写入正式事实。

### 3.4 真相和解释分区

- 事实字段、证据字段、AI 解释字段必须在页面结构上显式分开；

- 低保真原型中，所有 AI 字段都要附带“需人工审核”状态位；

- 风险点、节点、下撤点这类结构化真相，必须优先于自由备注。

## 4. 全局框架

## 4.1 页面壳结构

后台所有页面统一采用三段式骨架：

1. 左侧一级导航
2. 顶部上下文栏
3. 主内容工作区

统一布局建议：

- 左侧导航固定宽度；

- 顶部上下文栏固定展示当前路线、状态、最近更新时间；

- 主内容区允许二栏或三栏变化，但不做嵌套多层标签页。

## 4.2 一级导航

- 候选池

- 路线工作台

- 审核中心

- 发布中心

- 物资与规则库

说明：

- MVP 不单独做仪表盘首页；

- 首次进入后台默认落在 `候选池`；

- 单条路线进入后，顶部面包屑统一显示：

  - `候选池 / 路线工作台 / {route_name}`

## 4.3 顶部上下文栏

统一信息：

- 路线名

- `route_id`

- 省份/城市

- 当前状态 `candidate / draft / pending_review / approved / published`

- 可信度等级

- 最近更新时间

统一动作：

- 保存草稿

- 查看缺项

- 返回列表

按状态动态显隐：

- `draft`：显示 `提交审核`

- `approved`：显示 `生成版本`

- `published`：显示 `查看发布历史`

## 5. 页面低保真定义

## 5.1 AD01 候选池列表页

### 页面目标

- 让团队从 30 条候选线中明确先做哪条；

- 把候选状态和正式录入状态分开。

### 低保真布局

```text
+-----------------------------------------------------------+
| 顶部筛选条：省份 | 城市 | A1/A2 | 建议状态 | 路线类型       |
+-----------------------------------------------------------+
| 左：候选表格                                  | 右：预览抽屉 |
| 路线名 | 区域 | 层级 | 新手适配度 | 风险备注 | 工作状态       |
| ...                                               ...    |
+-----------------------------------------------------------+
```

### 关键交互

- 点击表格行：右侧展开候选预览抽屉；

- 点击 `创建录入任务`：生成 `draft` 路线并跳转工作台；

- 点击 `新建草稿`：只填写最小事实包并触发 Agent 预填；

- 点击 `标记优先录入`：只改候选优先级，不进入正式录入；

- 点击 `标记淘汰`：要求填写淘汰备注。

### 关键状态

- `建议优先录入`

- `候补补证据`

- `淘汰`

- `已转 draft`

## 5.2 AD02 路线工作台总览页

### 页面目标

- 作为单条路线的唯一总入口；

- 用最少认知成本告诉录入员“还差什么”。

### 低保真布局

```text
+-----------------------------------------------------------+
| 顶部路线信息条 + 当前状态 + 可信度 + 主动作                |
+-----------------------------------------------------------+
| 左：进度总览卡                | 中：缺项列表 | 右：操作区     |
| 基础事实 完成/缺失            | Agent 待补参数 | 保存草稿      |
| 几何导航 完成/缺失            | 缺 1 下撤点   | 提交审核       |
| 风险天气 完成/缺失            | FAQ 未审核    | 查看 package   |
| 证据 FAQ 完成/缺失            | 用户上报 2 条 | 历史记录       |
+-----------------------------------------------------------+
| 下方：四个分区跳板卡                                        |
| 基础事实 | 几何导航 | 风险天气&checklist | 证据&FAQ        |
+-----------------------------------------------------------+
```

### 关键交互

- 点击分区卡进入对应录入页；

- 点击缺项项可直达对应字段页；

- `提交审核` 前先弹出门槛校验清单。

- `重新触发 Agent 补全` 作为显式动作存在于操作区。

### 关键状态

- `完成`

- `缺失`

- `待补证据`

- `不可提交审核`

- `Agent 补全中`

- `用户上报待审核`

## 5.3 AD03 基础事实录入页

### 页面目标

- 录入路线主表与标签事实；

- 保障前台发现页和详情页可被稳定聚合；

- 运营在本页只手填最小事实，基础参数区默认显示 Agent 建议值。

### 低保真布局

```text
+-----------------------------------------------------------+
| 顶部：路线基础信息 + 保存状态                               |
+-----------------------------------------------------------+
| 左：表单主区                                   | 右：校验侧栏 |
| A 路线身份                                      | 必填完成度   |
| B 基本参数（Agent 建议）                         | 标签是否齐全 |
| C 新手判断                                      | 最近核验提醒 |
| D 交通入口                                      | 前台影响模块 |
| E 路线标签                                      |             |
+-----------------------------------------------------------+
| 底部固定操作条：保存草稿 | 返回工作台 | 下一步去几何导航          |
+-----------------------------------------------------------+
```

### 表单结构要求

- 每组字段之间有明显标题分隔；

- AI 可起草字段旁显示 `AI 起草 / 待人工确认` 标记；

- 路线标签用结构化标签选择器，不用自由输入框。

- 基本参数区必须看得出 `Agent 建议值 / 人工确认 / 重新拉取地图结果` 三种状态。

### 关键校验

- 至少 1 个 `safety` 标签；

- 核心标签 1-3 个；

- 最近核验时间缺失时顶部显示黄色警示。

- 距离 / 时长 / 爬升缺失时，不是提示“人工补录”，而是提示“等待 Agent / 地图同步”。

## 5.4 AD04 几何、节点与导航录入页

### 页面目标

- 录入空间真相；

- 明确主线、关键节点、下撤点；

- 让“地图 API 同步结果”和“用户上报待审核提议”在同一页可被审核。

### 低保真布局

```text
+-----------------------------------------------------------+
| 顶部：几何版本 + 地图模式 + 保存状态                         |
+-----------------------------------------------------------+
| 左：地图工作区                              | 右：结构化侧栏 |
| 轨迹预览                                     | A 几何信息     |
| 起终点标记                                   | B 阶段列表     |
| 节点/下撤点/风险点覆盖层                      | C 节点列表     |
|                                             | D 下撤点列表   |
|                                             | E 用户上报待审 |
+-----------------------------------------------------------+
| 底部操作：保存草稿 | 返回工作台 | 下一步去风险天气页          |
+-----------------------------------------------------------+
```

### 关键交互

- 地图点选或列表双向定位；

- 点击节点列表项，地图高亮对应点位；

- 支持新增、复制、排序节点；

- 未设置起终点时，地图上方显示硬提醒。

- 点击用户上报项，可在地图上高亮提议点并做 `接受 / 驳回`。

### 必验提示

- 主轨迹是否存在；

- 至少 1 个关键节点；

- 至少 1 个下撤点。

## 5.5 AD05 风险、天气与 checklist 录入页

### 页面目标

- 录入“让新手不慌”的保守提醒与出发准备逻辑。

### 低保真布局

```text
+-----------------------------------------------------------+
| 顶部：风险完整度 + checklist 完整度                          |
+-----------------------------------------------------------+
| 左：风险点与天气规则                    | 右：checklist 画像 |
| A 风险点列表                            | 时长桶            |
| B 天气/时间规则                         | 强度桶            |
| C 用户上报风险待审                       | 地形/天气标签     |
|                                        | 必带/选带/加严物资 |
+-----------------------------------------------------------+
| 底部操作：保存草稿 | 返回工作台 | 下一步去证据FAQ页           |
+-----------------------------------------------------------+
```

### 关键交互

- 风险点列表与结构表单联动；

- checklist 物资从规则库选择；

- 支持 `复制相似路线画像`；

- 天气规则缺少 `rain` 或 `late_start` 时给出校验提示。

- 用户上报的风险点可直接转成正式风险点，或驳回并写原因。

### 必验提示

- 至少 1 个高优先级风险点；

- 至少 1 条天气或晚出发规则；

- 必带物资不为空。

## 5.6 AD06 证据来源与 FAQ 页

### 页面目标

- 让“为什么能进库”变成可审、可回溯对象；

- 让 FAQ 明确依附证据。

### 低保真布局

```text
+-----------------------------------------------------------+
| 顶部：证据覆盖度 + FAQ 审核状态                               |
+-----------------------------------------------------------+
| 左：证据来源表                          | 右：FAQ 列表       |
| 来源类型 | 标题 | 可信度 | 支撑字段       | 问题              |
| ...                                    | 回答              |
|                                        | 引用依据          |
+-----------------------------------------------------------+
| 中部提示条：官方类 / 地图类 / 体验类覆盖情况                  |
+-----------------------------------------------------------+
| 底部操作：保存草稿 | 返回工作台 | 提交审核前自检              |
+-----------------------------------------------------------+
```

### 关键交互

- FAQ 每条都必须挂载 `source_basis`；

- `AI 起草` FAQ 默认进入未审核状态；

- 证据覆盖提示始终固定在表格上方。

### 必验提示

- 是否达到“两类三份”；

- FAQ 是否全部人工审核；

- 是否存在关键字段无证据支撑。

- 是否仍有未处理的高优先级用户上报。

## 5.7 AD07 审核中心列表页

### 页面目标

- 审核员批量处理 `pending_review` 路线；

- 快速找到高风险或缺口明显的路线。

### 低保真布局

```text
+-----------------------------------------------------------+
| 顶部筛选：省份 | 证据覆盖不足 | 风险缺失 | FAQ 未审核        |
+-----------------------------------------------------------+
| 审核列表                                                     |
| 路线名 | 录入完整度 | 证据覆盖度 | 风险点数 | 建议可信度 | 提交时间 |
+-----------------------------------------------------------+
| 行内动作：进入审核详情 | 退回录入 | 标记待补证据                |
+-----------------------------------------------------------+
```

### 关键交互

- 列表支持快速过滤出“缺证据”“缺风险”“FAQ 未审”；

- 进入详情后不允许直接编辑字段，只能审核或退回。

## 5.8 AD08 单路线审核详情页

### 页面目标

- 让审核员对单条路线做最终判断；

- 把事实、证据、解释和结论分区展示。

### 低保真布局

```text
+-----------------------------------------------------------+
| 左：路线摘要卡      | 中：审核清单区              | 右：结论卡     |
| 基础事实            | A 准入红线                  | 通过           |
| 轨迹/节点摘要        | B 新手友好度                | 退回补充       |
| 风险摘要            | C 证据充分性                | 淘汰           |
| 证据摘要            | D 后台完整度                | 备注/原因      |
+-----------------------------------------------------------+
```

### 关键交互

- 审核清单全部打钩前，不允许 `通过`；

- 点击 `退回补充` 必须填写结构化退回原因；

- 点击 `淘汰` 必须填写淘汰原因并提示后果。

### 审核区分要求

- 左侧只能读，不可编辑；

- 中部只做勾检，不做自由散写；

- 右侧才是结论与备注区。

## 5.9 AD09 发布中心页

### 页面目标

- 承接 `approved` 路线；

- 生成版本、预览 package、完成正式发布。

### 低保真布局

```text
+-----------------------------------------------------------+
| 左：待发布路线列表                | 右：当前版本与发布动作       |
| 路线名 | 几何版本 | FAQ 版本       | package 摘要               |
| checklist 版本 | 历史发布         | 生成发布版本               |
|                                  | 预览 route package         |
|                                  | 确认发布                   |
+-----------------------------------------------------------+
```

### 关键交互

- 先 `生成发布版本`，后 `预览 package`，最后 `确认发布`；

- 若当前路线已有历史发布，显示版本摘要但不做复杂 diff；

- 不满足发布门槛时，右侧动作区显示不可发布原因。

## 5.10 AD10 发布记录与回退页

### 页面目标

- 查看发布历史；

- 进行暂停推荐、标记无效、恢复稳定版本。

### 低保真布局

```text
+-----------------------------------------------------------+
| 顶部：路线信息 + 当前生效版本                               |
+-----------------------------------------------------------+
| 发布历史表格                                                 |
| 版本ID | 发布时间 | 发布人 | checksum | 状态 | 动作            |
+-----------------------------------------------------------+
| 右侧抽屉：package 摘要 / 版本说明 / 回退提醒                 |
+-----------------------------------------------------------+
```

### 关键交互

- 查看 package 快照；

- 设为暂停推荐；

- 标记无效版本；

- 恢复上一稳定版本。

说明：

- 低保真阶段只验证“有历史、能看摘要、能做回退动作”；

- 不做版本级可视 diff。

## 7. 关键页面跳转

主流程跳转：

```text
候选池列表
-> 路线工作台
-> 基础事实录入
-> 几何导航录入
-> 风险天气与 checklist
-> 证据来源与 FAQ
-> 返回工作台
-> 提交审核
-> 审核详情
-> 发布中心
-> 发布记录
```

异常路径：

```text
审核详情
-> 退回补充
-> 路线工作台
-> 对应缺项页面
-> 再次提交审核
```

## 8. 原型验收标准

一份可用的后台低保真原型，至少应满足：

- 看得出后台一级导航和单路线工作台关系；

- 看得出每页主布局，不靠长文解释才能理解；

- 看得出 `事实 / 证据 / 解释 / 审核结论 / 发布动作` 的边界；

- 看得出 `提交审核` 与 `确认发布` 的门槛提醒；

- 看得出从候选到发布的完整主路径。

## 9. 当前明确不做

- 不做后台高保真视觉稿；

- 不做复杂组件规范和设计 token；

- 不做真实地图编辑器交互细节；

- 不做权限系统与多人协作流；

- 不做批量自动入库、批量审核、批量发布。

## 10. 下一步建议

有了这份说明后，下一步最顺的是二选一：

1. 按本文档直接实现 `后台静态原型 V1`
