## 2. 产品概述

### 2.1 一句话定义

- 面向徒步新手小白的 `精选路线库 + 路线跟随型导航` 产品，帮助用户从“不知道去哪”到“敢去、看得懂、走得稳、能回来”。

### 2.2 产品定位

- 本产品不是发烧友向的专业轨迹工具。

- 本产品不是开放式户外社区。

- 本产品不是通用地图平台。

- 本产品是面向新手的 `成熟公开路线选择工具 + 在途安心辅助工具`。

### 2.3 第一性原理

- 新手并不需要无限多的山。

- 新手真正需要的是：

  - 去那些本来就应该去、也更可能去的成熟路线；

  - 在出发前知道这条线适不适合自己；

  - 在途中知道自己有没有走对；

  - 在天气、时间和体力不匹配时及时收手。

- 因此，MVP 先解决 `路线选择正确性` 和 `在途安心感`，而不是追求地图系统完备性。

## 3. 目标用户

### 3.1 核心用户

- 徒步经验 `0-5 次` 的城市休闲型新手；

- 主要动机是健康、风景、周末放松、轻成就感；

- 对迷路、岔路、天气、电量、装备不足更敏感；

- 更愿意去 `成熟公开、交通可达、退出成本低` 的路线。

### 3.2 非目标用户

- 野线爱好者；

- 极限长线或穿越用户；

- 专业轨迹记录和户外数据分析重度用户；

- 以发帖、组队、社区互动为核心诉求的用户。

## 4. 核心问题与产品回答

| 用户问题      | 本质风险        | MVP 回答方式                  |
| --------- | ----------- | ------------------------- |
| 不知道去哪     | 路线选择困难，担心选错 | 精选路线库 + 标签 + 推荐解释         |
| 不知道自己能不能走 | 难度认知失真      | 新手适配说明 + 距离/时长/爬升 + 不适合条件 |
| 途中怕走错     | 岔路、偏航、环境不熟  | 路线跟随、关键节点提醒、偏航提醒基础能力      |
| 不知道何时该撤   | 时间规划失败、逞强   | 下撤提醒 + 不适合继续条件            |
| 担心天气变化    | 风险感知不足      | 天气 API + 官方预警入口           |
| 不知道带什么    | 装备准备不足      | AI 组合生成 checklist         |

## 5. MVP 目标

### 5.1 目标

- 验证新手用户是否愿意使用 `精选路线库 + 路线跟随型导航` 完成一次周末轻徒步出行。

- 验证“路线先筛选对，再在途中辅助判断”是否比“复杂路书图像生产”更适合个人开发者 MVP。

- 验证 AI 在 `推荐、解释、checklist 组合` 这三个层面是否能提升产品价值。

### 5.2 非目标

- 不做全国路线覆盖；

- 不做野线探索；

- 不做复杂 turn-by-turn 导航；

- 不做用户上传路线；

- 不做社区和 UGC；

- 不做自定义地图图像渲染生产链；

- 不做完整离线地图引擎。

## 6. 产品范围

### 6.1 路线库

- 首批只收录 `四川、浙江、广东、福建` 的成熟公开新手线。

- 首期规模建议 `20-30 条`。

- 每条线路必须满足准入标准后才能正式入库。

- 每条线路必须回答以下问题：

  - 这条线为什么适合新手；

  - 这条线最容易慌的点在哪里；

  - 什么天气或时间条件下不建议去；

  - 如果状态不对，应该什么时候撤。

### 6.2 地图与导航

- 使用现成地图底座承载路线显示与在途辅助。

- MVP 需要具备的在途能力：

  - 当前位置显示；

  - 路线轨迹展示；

  - 关键节点/岔路提示；

  - 偏航提醒基础能力；

  - 下撤点和风险提示；

  - 地形或海拔高差表达能力。

- MVP 不要求：

  - 复杂动态重规划；

  - 全量语音 turn-by-turn；

  - 自研离线底图体系。

### 6.3 AI 能力

- `推荐选线`

  - 根据省份、时间、强度、景观偏好、安全感偏好给出推荐解释。

- `路线资料整理`

  - 用于后台内容生产，不直接暴露给用户作为真相来源。

- `标签生成`

  - 从结构化物料中辅助生成标签候选。

- `摘要生成`

  - 将资料转成新手听得懂的路线摘要。

- `FAQ 问答`

  - 回答“这条线为什么适合我”“哪种情况不建议去”等轻问答。

- `checklist 组合`

  - 从系统物资库中按天气、强度、时长、地形进行组合和排序。

### 6.4 天气与预警

- 接入天气 API；

- 线路详情和在途页展示常驻天气提示；

- 支持跳转查看官方预警信息；

- 当天气不适合出行时，需要醒目提示。

## 7. 关键信息架构

- 首页

- 省份/城市路线发现页

- 路线详情页

- 出发前准备页

- 在途导航页

- checklist 页面/弹层

- FAQ/解释区块

- 天气预警详情页

- 安全说明页

## 8. 核心页面定义

### 8.1 首页

- 呈现产品定位：只服务新手轻徒步；

- 提供省份入口、精选主题入口、首屏推荐线路；

- 强调“成熟公开、适合新手”的选线逻辑。

### 8.2 路线发现页

- 支持按省份、城市、标签筛选；

- 支持按“更轻松”“风景更好”“更安心”快速筛选；

- 线路卡至少展示：

  - 路线名；

  - 城市/区域；

  - 时长；

  - 距离；

  - 爬升；

  - 1-3 个核心标签；

  - 一句适合新手的理由。

### 8.3 路线详情页

- 展示“为什么适合新手”；

- 展示“什么情况下不建议去”；

- 展示距离、时长、累计爬升、最佳季节；

- 展示入口、往返方式、路线主逻辑；

- 展示风险提醒、下撤逻辑、天气入口；

- 展示 AI 生成但受控的 FAQ/解释区块；

- 提供开始导航入口和 checklist 入口。

### 8.4 出发前准备页

- 强制展示 checklist；

- 支持按天气和路线特征动态调整物资优先级；

- 展示基础准备项、天气加严项、应急加严项；

- 展示不适合出发的条件提醒。

### 8.5 在途导航页

- 显示当前位置与推荐路线；

- 显示当前所处阶段；

- 接近岔路或关键节点时给出轻提示；

- 偏离主路线时给出基础提醒；

- 显示下撤点、天气风险、剩余建议时间；

- 文案优先回答“我是不是还走对了”。

## 9. 体验原则

### 9.1 选线原则

- 不让用户面对海量路线和抽象地图；

- 先缩小范围，再给出推荐理由；

- 参数为辅，适配解释为主。

### 9.2 在途原则

- 不强调专业术语；

- 不制造“产品替你承担全部判断”的错觉；

- 优先降低慌张感，强调及时收手和回撤。

### 9.3 安全原则

- 不鼓励野线、抄近路、未开发路径；

- 不夸大导航能力；

- 不把资料可得性误包装成路线确定性；

- 当风险不确定时，表达必须保守。

## 10. 路线内容标准

- 每条正式线路必须满足 `route-library-admission-standard-v1.md`；

- 每条线路必须沉淀以下最小内容：

  - 基础事实信息；

  - 适合新手的理由；

  - 不适合去的天气或时间；

  - 路线主逻辑；

  - 关键节点；

  - 下撤逻辑；

  - 证据来源；

  - FAQ 与标签；

  - checklist 组合条件。

## 11. 标签体系

### 11.1 主标签框架

- `景观审美`

- `安全感`

- `轻松成就`

### 11.2 扩展表达

- 景观审美：

  - `溪谷感`

  - `茶山视野`

  - `林荫感`

  - `适合拍照`

- 安全感：

  - `成熟步道`

  - `人流稳定`

  - `入口好找`

  - `撤离明确`

- 轻松成就：

  - `周末可完成`

  - `首次徒步可尝试`

  - `半天也能走`

## 12. 业务规则

- 只有 A 级可信度路线才允许进入正式路线库；

- B 级路线只允许内部评审，不允许对外展示为正式推荐；

- C 级路线直接淘汰；

- 推荐解释和 FAQ 必须基于当前已确认资料生成，不允许编造；

- checklist 必须基于结构化物资库进行组合，不允许完全自由生成；

- 天气明显不适合时，需要在详情页和在途页给出醒目提示。

## 13. 成功标准

- 用户能在 3 分钟内筛到一条看得懂、愿意去的路线；

- 路线详情页能有效回答“适不适合我”；

- 用户在出发前完成 checklist；

- 用户在途中能通过路线跟随和关键提醒降低慌张感；

- 首批路线库在质量上优先于数量，不因扩库牺牲可信度。

## 14. 数据与埋点建议

- 首页推荐点击；

- 路线发现页筛选使用；

- 路线详情页点击；

- 开始导航点击；

- checklist 完成率；

- FAQ 展开率；

- 推荐解释点击率；

- 天气预警点击；

- 在途页打开率；

- 偏航提醒触发次数；

- 下撤提示点击；

- 用户主观安心评分。

## 15. 风险与依赖

- 地图底座选型仍未最终确认；

- 小程序与 App 的载体决策仍会影响导航能力上限；

- 首批路线资料质量是核心风险；

- 天气与预警依赖外部供应商稳定性；

- AI 结果必须有受控边界，否则会误伤可信度。
