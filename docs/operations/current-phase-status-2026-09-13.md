## 5. RAG 使用边界

## 5.1 本阶段需要 RAG 的功能

### A. Agent 预填

- 目标：让 `summary_short`、`route_logic_summary`、`beginner_fit_reason`、FAQ、来源摘要不再主要依赖静态 prompt，而是先基于当前路线召回证据块后再生成。

- 价值：

  - 降低空泛总结和硬编内容；

  - 提升跨路线稳定性；

  - 让输出更容易被审核。

### B. 路线详情页追问 / 轻问答

- 目标：用户在路线详情页可继续追问，例如：

  - 这条线适不适合第一次徒步？

  - 雨天还建议去吗？

  - 我带老人或孩子是否合适？

  - 哪一段最容易慌？

- 价值：

  - 让当前产品从“静态路线页”升级为“路线级 AI 助手”；

  - 复用已有 FAQ、来源、天气规则和 checklist 画像；

  - 形成 MVP 可感知的 AI 能力。

## 5.2 本阶段不需要 RAG 的功能

### A. 天气 API 与天气展示

- 这是外部实时数据能力，不是知识检索问题。

- 应优先通过天气供应商 API + 规则模板实现。

### B. 出发前 checklist

- MVP 阶段应采用：

  - `物资库 + 规则引擎 + LLM 文案润色`

- 不应先做成检索式问答。

### C. 下撤倒计时建议

- MVP 阶段应优先采用规则逻辑：

  - 当前时间

  - 天黑时间

  - 剩余距离 / 海拔 / 路段类型

  - 天气风险

- 它更接近安全策略，不应先依赖 RAG。

### D. 结构化节点生成与后台审核增强

- 当前版本已有“证据驱动 + generation\_basis 追溯”，已满足 1.0 核心要求。

- 若继续在这里叠加 RAG，收益不如先做 Agent 预填和路线问答。

- 因此统一延后到 `2.0`。

## 6. 当前方案纠偏

### 6.1 需要明确停止的方向

- 不再把 RAG 扩大到结构化节点生成和后台审核层。

- 不再优先打磨复杂 C 端交互。

- 不再优先做大而全的全库 RAG 平台。

- 不再优先做长期用户交互策略设计。

### 6.2 需要收缩成 MVP 的方向

- RAG 只服务两类能力：

  - Agent 预填

  - 路线问答

- 检索范围只做“单路线内检索”，不做全库泛检索。

- 问答只做“路线详情页追问”，不做通用聊天产品。

## 7. MVP 快速方案

## 7.1 P0：18 条路线内容 Scale Up

- 直接复用 `POST /api/admin/routes` 批量创建 `18` 条路线草稿。

- 首批路线从 `docs/requirements/first-launch-30-route-candidate-pool-v1.md` 中选取。

- 只要求最小事实包：

  - `route_name`

  - `province_name`

  - `city_name`

  - `area_name`

  - `start_point_name`

  - `end_point_name`

  - `route_type`

  - `map_search_keyword`

## 7.2 P1：Agent 预填接入轻量 RAG V0

- 范围：仅做单路线内检索。

- 检索对象：

  - `route_sources`

  - `route_faqs`

  - `route_weather_rules`

  - `route_checklist_profile`

- 方式：

  - 先召回与当前字段最相关的 `top-k` 证据块；

  - 再喂给 Agent 预填模型；

  - 输出仍走受控字段，不开放自由发挥。

## 7.3 P1：路线问答 MVP

- 新增路线级问答接口，例如：

  - `POST /api/routes/:id/ask`

- 问答仅围绕当前路线展开。

- 回答优先级：

  - 结构化字段

  - FAQ

  - 来源摘要

  - 天气规则

  - checklist 画像

  - 必要时补少量外部实时信息

## 7.4 P1：非 RAG 必需能力

- 天气 API：

  - 接入供应商天气数据；

  - 输出天气摘要、预警状态、是否建议出行。

- checklist：

  - 基于现有物资库与规则生成出发前清单；

  - 路线详情页或准备页展示。

- 下撤倒计时建议：

  - 给出“最晚建议折返 / 最晚建议进入下撤路径”的保守提示。

## 7.5 P2：延后到 2.0 的内容

- 结构化节点生成接入更复杂的检索链路。

- 后台审核证据面板再做交互增强。

- 全库级 RAG、rerank、多路线知识图谱。

- 通用聊天式 AI 助手。

## 8. 当前阶段的成功标准

- 库中至少有 `18` 条真实路线样本。

- 大多数路线能够跑完：

  - Agent 预填

  - 地图同步

  - 结构化节点生成

- Agent 预填已使用轻量 RAG 上下文，而不是纯静态 prompt。

- 路线详情页已支持路线级追问。

- 天气、checklist、下撤倒计时已有 MVP 版本可演示。

## 9. 一句话结论

- 当前阶段的正确方向不是继续精修细节，而是：

  - 先把路线样本 `scale up` 到 `18` 条；

  - 再把 RAG 只收敛到 `Agent 预填 + 路线问答`；

  - 其余能力用规则、接口和已有事实层尽快补齐 MVP。
